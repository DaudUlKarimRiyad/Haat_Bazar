# Mid Project Assessment: MVP Implementation and Viva (30 Marks)

The Mid Project Assessment is an individual assessment worth 30 marks. Each student is required to implement a Minimum Viable Product (MVP) of a feature for their project.

**Deadline:** 11:59 PM on 4th Nov 2026  
**Submission Form:** [https://forms.gle/MUXbsWV2Zr6fTKPt9](https://forms.gle/MUXbsWV2Zr6fTKPt9)

## 1. MVP Implementation Requirements

Your MVP must include the following:

* **Frontend:** Implement all Create, Read Single, Read List, Update, and Delete (CRUD) functionality using modern functional React (TypeScript).
* **Backend:** Implement Create, Read Single, Read List, Update, and Delete functionality through the appropriate REST APIs using FastAPI (Python).
* **Database:** Implement the required database model(s) and integrate them with the backend if your feature involves database changes; Supabase is recommended.
* **Integration:** Ensure that the implemented feature is fully functional and integrated into your existing project.

**Important:** All pull requests (PRs) must be merged into the main branch before the assessment to ensure that your latest code is available and up to date.

## 2. Mark Distribution

| Assessment Component | Marks |
| :--- | :--- |
| Frontend Implementation | 10 |
| Backend Implementation | 10 |
| GitHub Presentation (Issue, PR, Feature Branch Conventions and Viva) | 10 |
| **Total** | **30** |

## 3. Feature Demonstration Requirements

Each student must demonstrate their implemented MVP and be prepared to:

1. **Demonstrate the feature:** Show all implemented CRUD functionality in the frontend.
2. **Explain the request flow:** Use browser Developer Tools to demonstrate and explain how requests travel from the frontend to the backend, including the relevant API requests and responses.
3. **Explain the REST APIs:** Identify the endpoints used by the MVP and explain the purpose of each endpoint, including Create, Read Single, Read List, Update, and Delete operations.
4. **Invoke APIs using Postman:** Demonstrate the relevant API endpoints live in Postman if requested.
5. **Explain the database integration:** If the feature involves database changes, explain the relevant database models, relationships, and how the backend interacts with the database.

## 4. Important: Vercel Deployment

You are expected to demonstrate your work using your project's Vercel deployment URL configured during our first class, when we initialized the project.

If you cannot demonstrate the feature using the Vercel deployment, you will need to demonstrate it locally. Failure to demonstrate your work will result in a deduction of 10 marks, as the mid-project assessment will be considered incomplete and will be partially graded.

Please verify your deployment and ensure that all required functionality works before the assessment. Using the live deployment is strongly recommended to avoid unexpected technical issues.
